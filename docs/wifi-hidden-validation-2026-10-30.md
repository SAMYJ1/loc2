# 同网无线隐藏模式验证

日期：2026-10-30。结论：隐藏模式的同网无线链路在相同代码重连后通过完整120秒验证；两个地图采用西溪天街，Mac无投屏窗口，停止后无需刷新定位服务即恢复真实位置。首轮发生连接重置，稳定性仍需进一步验证。

## 范围与条件

- 采用原实验控制器，使用 Wi-Fi 承载 CarPlay、蓝牙承载手机实际订阅的位置数据；USB 拔出。
- 目标仍为龙湖杭州西溪天街，WGS84 纬度30.2961347、经度120.0646261。
- iOS 27.0 / 24A435；开始前直接查询开发者模式 enabled。沿用上一轮用户确认的同网、蓝牙、VPN开启和真实位置基线。
- helper SHA-256 固定为 `40f89f1bfbb183c028a169f7a40a89f88c3a0300d9cc5b0c53ea3202af7f58f5`。
- 在刚通过的[无线可见模式预热修正](wifi-xixi-diagnosis-2026-10-30.md)上，用仓库 `tools/usb_validation/prepare.py` 生成独立隐藏运行目录。保留建连前插件初始化，不重编译 helper。
- 隐藏方式沿用[USB已验证实现](hidden-mode-validation-2026-10-30.md)：只将展示调用改为准备隐藏窗口，保留接收、解码、首帧判据和完整媒体会话。
- 启动前 Node 模块解析核对为 sameMediaModule=true；认证、真实首帧解码、hiddenVideoValidation=true 且 showCarPlay=false 后，才创建 ARM_LOCATION。真实位置订阅仍是供数前提。

首轮停止后，用户确认两个 App 均在真实位置，再重连。重连仅新建会话目录，运行时、配件身份、目标点及网络参数不变。

## 隐藏的证据

- 运行时只发出 showCarPlay=false / hiddenVideoValidation=true。
- 对接收进程使用 CoreGraphics 屏幕窗口元数据检查，只统计该PID的屏幕窗口，不采集屏幕图像。已观察到可见窗口数为0。
- 用户独立确认 Mac 没有 CarPlay 投屏窗口。
- 实际解码帧计数大于0，窗口隐藏没有绕过首帧判据。
