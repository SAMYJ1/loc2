# 开发检查记录

2026-10-29。集成基线为 `eb44200`；本记录覆盖该基线的最终审查修复。真实 USB、Safari、实际局域网和 Apple 地图坐标校准仍由 [Issue #9](https://github.com/SAMYJ1/location-lab/issues/9) 验收。

## 已修复的审查问题

- **构建部署目标**：新编译器默认产生最低 macOS 28.0 的二进制，虽能编译签名，却在当前 macOS 27.0.1 启动时报系统版本不兼容。构建现显式指定当前架构的 macOS 13.0 目标，并核对二进制与应用声明一致。修复后的真实应用已打开，详情及配对窗口可读；未点击应用位置或连接 USB。重复构建同时移除已删除的旧 Python 模块，已用打包目录中的临时旧模块验证清除。
- **位置观察确认**：确认操作现携带状态版本；采用确认还要求当前目标已报点，不能把 A 的延迟确认标到刚切换的 B。恢复确认同样不能跨越后续会话。公开会话服务回归先失败，修复后通过。
- **Mac 审批选择**：菜单按请求 ID 保留选择。合成原生界面检查中，选中 B 后移除前面的 A，批准记录仍为 B；移除已选中的 B 并添加 C 后，选择回到提示项，点击批准未产生新记录。撤销授权列表采用同样的稳定 ID 选择规则。检查使用独立假进程，不导入或启动 USB 后端。
- **手机连接状态**：物理 USB 是否连接与会话是否停止分别显示。浏览器回归覆盖停止后拔线、再接线，状态随设备变化更新且会话不自动恢复。

## 接收进程测试的时序波动

审查前的完整测试曾两次出现本地接受批次为零的失败，后续探针未捕获原始原因，不能宣称已证明生产传输存在故障或找到该历史失败的根因。

原测试把进程启动、订阅和供数放在同一个三秒循环中。现先通过公开状态等待外部替身的真实订阅事件，再用受控时钟触发一次供数，并等待其队列事件；超时时输出状态诊断，替身按换行边界读取完整请求。原有接受批次、入队、停止时限和日志压力断言均保留，修订后的测试及完整测试通过。这些检查不代表真实手机已采用或恢复位置。
