# 西溪天街同一 Wi-Fi 定位验证步骤

验证日期：2026-10-30。

后续复测发现：把整套运行时复制到新路径后，首次 GStreamer 插件扫描可能阻塞会话并导致首帧失败。使用新副本前，应先完成建连前初始化；原成功轮的历史过程保持如下，修正与重新验证见 [首次扫描阻塞诊断](wifi-xixi-diagnosis-2026-10-30.md)。

本轮使用原实验控制器，在 Mac 与 iPhone 连接同一普通 Wi-Fi、USB 全程拔出的条件下，将目标位置设为龙湖杭州西溪天街。用户确认无需刷新定位服务，Apple 地图和高德的当前位置蓝点均到达测试点并保持稳定；测试结束后，两个 App 均恢复真实位置。

## 验证条件

| 项目 | 本轮状态 |
|---|---|
| 手机系统 | iOS 27.0，build 24A435 |
| 开发者模式 | 开启；测试前后均直接查询为 `enabled` |
| 网络 | Mac 与 iPhone 连接同一普通 Wi-Fi，WPA2 Personal，信道36 |
| 蓝牙 | 复用 Mac 与指定 iPhone 既有的配对和连接信息 |
| USB | 启动前、运行中及结束后均确认未连接 |
| 手机 VPN | 用户确认开启，测试中保持不变 |
| 起始位置 | 用户确认地图当前显示真实位置 |
| 发送设置 | 每秒一次，位置发送窗口最多120秒 |

实际路径为：**蓝牙完成配件协商，Wi-Fi 承载 CarPlay 会话，位置数据走手机实际订阅的蓝牙 iAP 通道。** 本轮称为同网无线验证，不等同于纯 Wi-Fi 报点。

## 操作步骤

### 1 准备手机和连接环境

保持 iPhone 解锁，将手机与 Mac 连接到同一普通 Wi-Fi，保持蓝牙可用，拔掉 USB。确认开发者模式开启，手机 VPN 保持本轮的开启状态。

打开 Apple 地图，点击“当前位置”，确认蓝点显示真实位置。确认的是当前定位蓝点，不是搜索标记或地图中心。

### 2 核对 Mac 上的测试环境

确认没有上一轮接收端或报点进程残留，并核对 helper 的哈希与上述固定版本一致。每次使用新的运行目录，保留相同的配件身份和指定 iPhone 信息。

读取当前 Wi-Fi 的名称、信道和安全类型，确认与已保存的测试网络一致后再使用对应配置。本轮只读取网络元数据，没有重新查询钥匙串密码，也没有在报告中显示网络凭据。

通过设备直接查询确认开发者模式为 `enabled`，同时确认 USB 连接数为零。

### 3 设置无线测试参数

使用原控制器 `macplay_location_mvp.py`，本轮关键参数如下：

| 参数 | 值 |
|---|---|
| `--transport` | `lan` |
| `--location-lane` | `bluetooth` |
| `--lat` | `30.2961347` |
| `--lon` | `120.0646261` |
| `--duration` | `120` |
| `--max-runtime` | `360` |
| `--allow-resubscribe` | 启用，收到 Stop 时暂停、再次 Start 后允许恢复 |

网络配置仅引用本机受限文件，绑定当前网络和指定 iPhone。`360` 秒是包含建连等待的总运行上限；`120` 秒从实际开始报点时计算，重新订阅不会重置这段计时。

### 4 建立会话后再放行报点

先启动接收端，等待配件认证通过和 CarPlay 视频首帧成功解码，再创建本轮的 `ARM_LOCATION` 标记。

标记放行后，控制器仍需等到手机真实发出蓝牙位置 Start 请求，才开始每秒提交位置。收到 Stop 时暂停，避免把“接收端已启动”当成“正在提供位置”。

本轮认证在启动后约5.4秒通过，约7.1秒解码首帧，约11.0秒在手机重新订阅后开始报点。

### 5 先观察是否自然采用

在 iPhone 的 Apple 地图点击“当前位置”，观察约10秒，比较蓝点是否移动到西溪天街。

**本轮没有先关闭再开启定位服务。** 用户在这一步反馈“不用刷新就到了西溪天街”，因此没有继续执行备用的定位服务刷新步骤。

### 6 验证两个 App 的蓝点

分别在 Apple 地图和高德点击“当前位置”，保持网络、VPN、开发者模式和定位服务设置不变，观察约20秒。

本轮用户确认“两个 App 都稳定在西溪天街”。这项手机观察用于判断位置采用；本地发送或入队计数只用于核对数据链路。

### 7 等待自动停止并检查清理

保持现状，让120秒位置发送窗口结束。控制器结束无线会话并退出测试进程，再检查接收端、helper、蓝牙桥和控制器均无残留。

同时检查 USB 仍未连接、网络接口地址没有变化，并再次直接查询开发者模式。本轮结束后仍为 `enabled`。

### 8 验证真实位置恢复

停止后，在两个地图中再次点击“当前位置”，等待新的真实位置。如果仍停留在西溪天街，才将定位服务关闭约10秒再开启，然后重新观察。

本轮用户确认“两个 App 都已恢复真实位置”。用户没有说明恢复时是否执行了上述条件性刷新，因此记录为**恢复已确认**，不写成“停止后自动恢复”。
