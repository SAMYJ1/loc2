# USB 定位应用方案与访谈记录

更新：2026-10-29。状态：**用户已确认，方案定稿。** 本轮完成调研和设计文档，未开始应用实现或新一轮真机测试；下文技术验证项目继续保持未验证状态。

## 已确定的产品边界

1. 个人使用，单台 Mac 和一台 iPhone，先完成固定点流程。
2. 手机选点指令可以经过同一 Wi-Fi；提供位置数据始终走 USB。
3. Mac 首次确认配对授权，此后由手机直接应用，不逐次要求回 Mac 点确认。
4. 手机入口为 Safari 网页，可添加到主屏幕；不要求安装开发签名 iPhone App。
5. 手机切到地图或锁屏后，由 Mac 继续报点直到手动停止；这是产品目标，长时间和锁屏场景仍待验证。
6. USB 断开、Mac 睡眠、应用退出结束会话；重连后需在手机再次点应用。
7. Mac 日常菜单栏运行，按需打开详情，CarPlay 画面默认不展示；需先验证保留必要接收与解码但隐藏展示的模式。
8. 持久保存该手机浏览器对指定 USB iPhone 的控制授权；Mac 可以撤销。更换浏览器、清除网站数据或授权失效时重新配对，不能把同网或浏览器名称当作设备身份证明。
9. 可以在未接线时选好目标作为草稿，USB 连接就绪后仍须在手机点击“应用位置”；不排队自动执行。
10. 手机选点优先 Apple 地图，提供地点搜索、地图点选、明确标注的 WGS84 坐标输入与常用点收藏。地图服务接入验证仍是实现前提。

## 当前设计树

- 使用范围 → 个人、单 Mac/手机（已定）。
- 手机入口 → Safari/主屏幕（已定）→ Apple 地图搜索/点选、WGS84 输入与收藏（已定）→ 当前网络、域名与地图令牌验证（待验证）。
- 指令通道 → 同网 Wi-Fi（已定）→ 持久配对授权、Mac 可撤销（已定）。
- 执行通道 → USB（已定）→ 断线不自动恢复（已定）→ 未接线时草稿、接线后手机明确应用（已定）。
- 持续策略 → Mac 持有已接受目标，页面退后台仍继续（已定）→ 无固定自动停止时长（当前选择为手动停止）。
- Mac 形态 → 菜单栏和按需详情（已定）→ 隐藏画面技术验证（待验证，不是用户决策）。
- 验收 → 现有固定点行为证据；新应用闭环、切点、锁屏、持续运行、恢复均待验证。
- 最终共同理解 → 用户已确认完整方案，包括收藏保存在 Mac；本次确认使设计定稿，不自动开始应用编码或再次真机报点。

## 研究结论

可以设计为“手机选点 → 同网提交 → Mac 接受 → USB 报点”。这是基于平台能力与现有后端的工程可行性判断，尚不是完整手机控制流程的真机成功记录。此前 Wi-Fi CarPlay 定位失败不能直接否定这条链路，因为这里 Wi-Fi 只传用户指令。

手机网页不负责直接更改 iOS 系统位置，也不负责每秒供数。Mac 接受目标后管理整个会话，处理手机真实位置 Start/Stop 请求。界面分别表示目标请求已接受、USB 已连接、正在报点、位置变化已由用户确认和恢复待确认。

## 可复用资产与缺口

以下资产目前保存在原调研工作区，尚未迁移到本仓库；本仓库以设计文档起步。

- `outputs/PeripheralLocationMVP`：已有 AppKit 输入界面和离线状态核心，含坐标检查、旧会话隔离、限速和睡眠撤销；尚未接真实传输。
- `outputs/macplay_location_mvp.py`：真实 USB 固定点测试控制器，启动时指定坐标，使用隔离运行目录、目标手机和本地控制 socket；没有手机控制 API。
- MacPlay Rust helper：已有 `location` 命令和按手机订阅提供位置的路径；本地接受或入队仅证明后端处理，不能等同手机采用。
- Receiver：现有代码显示视频窗口，关闭窗口会触发 shutdown，视频超时会结束会话；先验证隐藏展示，不能直接删掉媒体链路。
- 当前依赖用户此前授权的第三方实验配件身份；自用方案继续显式保留这项依赖，不把它称作正式可分发认证能力。

## 候选交互流程

### 首次使用

1. Mac 打开应用；在只有指定 iPhone 通过 USB 连接时，显示设备与配对二维码。
2. 手机 Safari 打开 Mac 的同网控制页。二维码建立的是一次待确认的控制端配对，不自动授权局域网内其他页面。
3. Mac 展示控制端请求和目标 USB iPhone；用户确认一次，建立可撤销的持续授权。
4. 手机添加主屏幕入口。Safari 与主屏幕窗口的授权是否共享须实测；必要时对该入口单独完成首次配对。

### 日常使用

1. Mac 应用运行，两端同网；手机在控制页准备选点草稿。可以尚未连接 USB。
2. USB 接线就绪后，手机显示目标设备及当前连接状态，用户点“应用位置”。
3. Mac 校验授权、目标手机、请求新鲜度和坐标，接收目标并管理持续会话；无需每次回 Mac 确认。
4. 手机可切到 Apple 地图、高德或锁屏；Mac 继续处理已接受目标和手机真实 Start/Stop 请求。
5. 手机控制页或 Mac 菜单栏可停止报点。Wi-Fi 失联时控制页无法下新命令，Mac 菜单栏仍是可用停止入口；USB 会话是否健康单独判断。
6. USB 拔线、Mac 睡眠或应用退出撤销当前会话；重新连接后需重新点应用，不重放旧请求。
7. 显示“已停止报点”，由用户检查是否恢复真实位置；必要时引导手动关闭再开启定位服务。不能承诺一键自动恢复系统位置。

未联网地图和 Mac 关闭时手机能否离线准备草稿尚未作为承诺；当前“未接线”仅表示无需 USB，控制页仍需可访问 Mac。

## 实现边界建议

| 部分 | 职责 | 不持有的职责 |
|---|---|---|
| 手机控制页 | 选点草稿、目标提交、状态、停止入口 | 每秒供数、配件认证、直接设置系统位置 |
| Mac 应用 | 配对授权、目标设备、已接受目标、会话生命周期、状态与撤销 | 假定浏览器即 USB 手机、仅凭发送计数宣布成功 |
| 本机后端适配器 | 启停隔离进程、位置命令、真实订阅与断线事件 | 公网监听、接受未授权网页直接调用 |
| MacPlay USB 链路 | 已有认证、配件通信与位置消息提供 | 手机 UI、请求授权、用户业务状态 |

实现时不把 Rust helper 的本地控制 socket 直接暴露给局域网；只暴露应用自己的有限操作。每个新会话具有独立身份，旧请求、重试和延迟停止事件不得影响新会话。坐标必须携带来源及参考系，后端继续使用已验证的 WGS84 输入。

局域网入口需验证可达性、稳定地址、Safari 原点与授权保存方式。网页同源、配对凭据、来源校验与撤销是首次授权能够成立的必要条件；完整离线缓存、受信任 HTTPS 部署或公网访问不自动包含在当前方案内。

## Apple 地图接入与坐标契约

用户选择 Apple MapKit JS 作为首选地图。需要可用 Maps token；签名私钥如需使用，只保留在 Mac，网页使用面向页面的受限令牌。当前是否已有开发者账号及可用令牌尚未查询，不注册账号、不新增付费服务；实现时先确认这些前提。

官方文档提供 token 的 Domain/None 限制和动态签发的 origin 要求，但本轮未取得私网 IP 或 `.local` 长期域名限制的明确支持保证。因此先验证实际手机 Safari、Mac 局域网 URL、令牌限制、地图加载和地点搜索，再完成完整选点界面；失败时保留坐标输入，重新讨论地图接入方式，不静默换供应商。

Apple 原生 `CLLocationCoordinate2D` 使用 WGS84，但这不足以单独证明 MapKit JS 中国区域的地图点选、搜索结果和后端位置能无偏差衔接。保存 `inputCoordinate`、`inputCRS`、`provider` 与 `normalizedWGS84`；用已知点校准搜索与拖动点选后再传给现有 NMEA 后端。只有明确标为 WGS84 的手工坐标可直接走既有校验路径。

曾比较高德作为备选：其官方坐标为 GCJ-02，`convertFrom` 支持 GPS 等向高德转换，官方不提供转回 GPS/WGS84 的接口，另需转换评估与校准；用户本轮未选择高德。

参考：[Apple Maps token](https://developer.apple.com/documentation/mapkitjs/creating-a-maps-token)、[MapKit JS Coordinate](https://developer.apple.com/documentation/mapkitjs/coordinate)、[原生 CLLocationCoordinate2D](https://developer.apple.com/documentation/corelocation/cllocationcoordinate2d)、[高德坐标说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)、[高德接口边界](https://lbs.amap.com/faq/basis/location/1060046657/)。

## 建议的应用界面

手机控制页上方显示 Mac 与目标手机连接状态，中间为 Apple 地图/搜索，坐标输入与收藏作为替代入口，下方始终提供“应用位置”和“停止报点”。未接线时可以修改草稿，应用按钮不可触发执行。已经报点时，选新点只改变草稿，点击应用才替换当前目标，避免地图拖动直接改变正在提供的位置。

Mac 菜单栏显示未连接、就绪、正在报点或异常；菜单提供停止、打开详情、配对/撤销和退出。详情展示目标手机、目标位置、当前会话与恢复提示，不将配件认证、队列统计等作为主操作流程。

收藏保存在 Mac，手机通过已授权控制页读取；这与第一版“Mac 运行并同网”的前提一致，避免出现两端各自一套收藏。用户已随完整方案确认该条。

## 实施顺序建议

1. **验证关键前提**：真实 USB 会话隐藏画面后仍健康；Apple 地图在实际局域网入口可加载和搜索；坐标对应关系可校准。出现阻碍先记录并调整设计。
2. **Mac 应用接入后端**：将离线 UI/状态核心与真实 USB 后端适配，菜单栏启停、设备绑定、真实 Start/Stop、异常和睡眠清理；先用明确 WGS84 坐标验收。
3. **手机控制闭环**：二维码配对、一次 Mac 授权、持久凭据与撤销、目标草稿、应用/停止/状态；网页退后台不影响 Mac 持有的会话。
4. **选点体验**：Apple 搜索和点选、坐标输入、收藏；验证持续会话中 A/B 切点，不因切点重放旧请求。
5. **个人使用验收**：首次与再次连接、锁屏、长时间运行、Wi-Fi 指令通道中断、USB 拔线、Mac 睡眠/退出、撤销授权，以及停止后的真实位置恢复。通过后再把各项从“设计目标”改为“已支持”。

不把完整原生 iPhone App、完全不依赖局域网的手机控制、无线定位、离线地图、路线移动、多设备、开机自动执行和公开分发包含进第一版。

## 已有证据的边界

[USB 开发者模式对照摘要](validation-baseline.md)中直接查询为 disabled 的组出现过测试位置，但紧接成功开启组，不能推广到全新设备。没有原生位置来源样本；停止、拔线与恢复不同步。新的控制页面不需要为了自身安装开启开发者模式，但也不会消除配件链路已有的不确定性。

## 平台依据

- [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)：Safari 的局域网流量属于所列本地网络权限例外；普通原生 App 的网络权限条件不同。网页应直接打开 Mac 提供的同源控制页，不能假定公网 HTTPS 页面可任意请求局域网 HTTP 服务。路由、VPN、防火墙和当前 iOS 版本仍需实测。
- [Apple：网页添加到主屏幕](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios)：支持网页作为主屏幕入口。这不等于已经承诺完整离线 PWA、后台持续执行或跨网络可达。
- [Apple MapKit JS](https://developer.apple.com/maps/web/)：提供网页交互地图、标注及可拖动标注；地图服务授权及具体提供方尚未定案。
- [Apple Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)：开发签名运行与 App Store/TestFlight 分发的要求不同；网页入口避免新增开发签名手机 App。
- [WebKit WebUSB 立场](https://github.com/WebKit/standards-positions/issues/68)：Safari 网页直接通过普通 USB 线控制 Mac 不作为支持承诺。
- [PeerTalk](https://github.com/rsms/peertalk)：原生 iPhone TCP 服务与 Mac usbmux 通信有上游先例；尚未验证与本项目 CarPlay 并发，也不是用户选定的第一版路径。

## 下一步技术验证，尚未执行

1. 保留 USB 配件/媒体会话，隐藏视频展示，验证不会因窗口状态退出。
2. 手机网页提交一个目标，Mac 可见并绑定至当前授权手机；未授权端不能应用。
3. 持续 USB 会话中切换 A/B 目标，验证不是只改界面或本地计数。
4. 网页切后台/关闭、手机锁屏、Wi-Fi 指令通道断开时，区分“不能再下指令”和“USB 位置会话仍持续”。
5. USB 拔线、Mac 睡眠、退出后结束会话；重连不恢复旧目标，不重放旧请求。
6. 将“停止报点”和“恢复真实位置”分别验收，保留手动刷新定位服务的引导。

访谈结束，用户已确认共同理解。后续实现须由用户另行发起；开始时先完成上述技术验证，再推进应用闭环。
