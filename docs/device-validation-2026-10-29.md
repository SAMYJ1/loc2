# USB 真机验证：2026-10-29

结论：**USB 认证、真实订阅及本地报点可运行，但本轮没有观察到手机采用测试位置，位置采用验收未通过。** 不能用本地接受或入队计数替代手机观察。

## 条件

- 应用代码基线：`7d63593`，通过实际 `USBBackend` 与 `SessionService` 运行限时测试。
- 同一台通过 USB 枚举绑定的 iPhone；设备清单报告 iOS 27.0（24A435）。用户确认 VPN 关闭。
- 使用此前已授权的本机认证与配对身份，复制到仓库外私有运行目录；原实验目录未修改。未更改开发者模式。
- 固定目标 WGS84 31.2304、121.4737，沿用之前的验证点。新适配器与旧实验控制器在相同时间、坐标下生成的 NMEA 字节完全一致。
- 初始 USB 物理层看到了 iPhone，但 usbmuxd 只报告网络连接。用户重新插拔并直连后，恢复为一台 USB 设备；没有修改枚举代码或使用网络设备冒充 USB。

## 证据边界与后续

- 本轮未执行 A/B 目标切换、锁屏长时运行、Mac 睡眠、手机网页配对和实际地图令牌校准。
- 隐藏模式未报告首帧，而之后的可见模式报告了首帧。这是差异线索，但轮次顺序和手机初始化状态可能影响结果，不能仅凭一次对照确认隐藏实现是根因。
- 可见模式已解码却仍未观察到位置采用，因此视频启动成功也不是位置采用的充分证据。
- 下一步先在相同现场条件下对照完整旧控制器与新适配器，并保留独立手机观察；在定位原因前，不扩大为兼容性或验收成功结论。
- 脱敏机器结果保留本机；认证材料、设备标识和原始敏感日志未加入仓库。

已直接回看原会话“调研 Mac 外设定位并做 MVP (2)”的成功测试顺序，并与固定协议和连续性记录对照：

- 原成功的关闭开发者模式组紧接开启组成功之后；原会话也有关闭模式下认证/视频/报点正常而未采用的失败记录。成功不能推广为任意初始状态都可复现。
- **此前选取的运行资料不是成功组的完整身份。** 三轮测试证书与原成功组一致，但 CarPlay 长期公钥、私钥和配对标识来自另一个实验目录，均不同于原 `ab-on` 成功组。此前认为“复用了相同身份”的判断不成立。

新增第四轮只将 CarPlay 身份恢复为原成功组，保留当前二进制、新适配器及可见视频模式。原身份文件通过当时的私有连续性清单验证；材料在仓库外隔离复制，未改动原实验目录。测试前直接设备查询确认 `developerModeStatus=disabled`、iOS 27.0（24A435）。

## 当前结论与收尾

- **不是仅换回旧控制器或原配对身份即可恢复。** 当前条件下，旧控制器在视频就绪后报点、并在有效窗口内刷新定位服务，也未复现位置采用。
- 原历史成功的关闭组紧接开启组成功，初始化或状态保留仍是未排除的变量。不能据此断言必须开启开发者模式，也不能保证关闭模式独立可用。
- 原 helper 二进制未在已检查位置找到完整旧版本；最新二进制来自后续热点配置重编译。代码记录显示对应变更为无线安全类型选择，尚无证据将 USB 失败归因于该变更。
- 用户选择保持开发者模式关闭、先保存排查结果，因此未执行新的开发者模式开启/关闭对照，也没有为追求成功修改其他安全设置。
- 最终直接设备查询再次确认 `developerModeStatus=disabled`，iOS 27.0（24A435）；用户确认真实位置、定位服务开启、状态正常。测试接收进程数为零。
- 验收继续保持未通过。后续如继续排查，应先确定能取得的历史二进制或更直接的位置来源证据，以及是否另行授权改变初始化条件；不盲目重复相同报点实验。
