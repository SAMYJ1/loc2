# 原生手机 App 与 Mac 后台服务：需求访谈

日期：2026-10-30。状态：用户已最终确认，进入实施。2026-10-30 用户回复“确认”，授权按本稿实现；技术选择由助手负责。

## 用户明确的新方向

- Mac 仅运行后台服务，保留必要的调试入口。
- 原生手机 App 扫码连接 Mac 后台服务，直接完成地图搜索、选点、应用目标与恢复流程。
- App 集成地图并实时获取系统报告位置，日常操作不要求切换到其它地图 App。
- App 提供常用地点收藏。

上述方向替换旧方案的 Safari 主入口和 USB 日常定位边界，见拟议 ADR-0002。原 USB 能力及历史验证记录保留。此前已确定的个人单 Mac / 单 iPhone、选点草稿不自动执行、明确应用、授权持久保存、断线不自动重放目标等规则继续作为基线。

## 已有事实与边界

- 已有 Mac 菜单栏、会话服务、手机网页授权及收藏逻辑可以评估复用；原生 iPhone 控制端尚未实现。
- Wi-Fi 承载 CarPlay、蓝牙承载位置数据的隐藏模式已完成一次完整120秒固定点采用及恢复；首轮曾发生连接重置，不能扩大为长时间、锁屏和任意网络条件已通过。
- 应用后端目前仍为 USB；无线能力在独立实验运行时中。
- 用户说的“恢复”需要拆成恢复请求、已停止报点、系统报告位置更新、恢复状态，不能将停止请求的成功回执当作真实位置已恢复。
- 原生地图和位置观测推荐 SwiftUI + MapKit + Core Location；Mac保留独立会话执行能力。现有网页Cookie/Origin授权协议需要适配原生客户端，不能直接视为已完成扫码连接。
- 系统位置样本需检查时间、精度及可选来源字段；外设来源标记不提供具体配件身份，也不能独立证明全系统位置采用或恢复。公开定位API未提供普通App强制重置全系统位置的接口。
- 前台定位观测与Mac持续报点是不同生命周期；不需要为了Mac继续报点而让iPhone后台持续采集位置。

## 设计树

- 产品范围：个人单 Mac / 单 iPhone（沿用）；原生手机主入口、Mac后台（新需求明确）。
  - Mac默认手动启动，可选登录自启动（Q1已确认）；开启服务不自动应用位置。
  - Mac不在线时，手机仍可使用有网地图、系统位置、收藏与草稿（Q2已确认）。
    - 技术建议：手机保存可独立使用的收藏与草稿，连接Mac时兼容迁移现有收藏；不要求云账号，不承诺离线地图。
  - 手机切后台、锁屏或划掉App不直接结束Mac会话；App只在前台持续观测系统位置（Q3已确认）。
    - 回到前台读取实际会话，不重放旧草稿；锁屏及持续运行仍须真机验收。
  - 首次配置尽量无线（Q4已确认）；优先复用当前设备已有网络配对，不把USB作为用户流程的默认前置条件。
  - 首版免费Personal Team签名；完善后再考虑付费与上架（Q5已确认）。
- 连接与授权：扫码、首次Mac确认、后续持久授权（沿用）；无线优先，系统首次配对与App授权分开引导。剩余工具链与配对能力问题作为技术验证，不再向用户询问技术选型。
- 选点与地图：地图主界面、顶部搜索、底部目标卡、系统位置与目标分开显示（Q6已确认）；收藏列表与最近使用（Q7已确认）。
- 应用与恢复：明确应用（沿用）；恢复单击执行，等待系统新定位并展示观察结果，不能确认时保留提示（Q8已确认）。
- 电源与时长：报点期间防普通闲置睡眠，允许息屏；主动睡眠结束，停止后解除唤醒（Q9已确认）；首轮连续2小时验收，不是强制时限（Q10已确认）。
- 技术方案、异常场景与验收顺序：见下方，由助手负责落实。
- 访谈已完成：全部使用体验问题与最终共同理解均已确认。

## 第一轮结论

Q1：用户选择不默认自启动，保留配置项。Mac服务默认手动开启，日常不弹主窗口；配置界面提供开关，任何启动方式都不自动应用目标。

Q2：用户确认Mac不在线但手机有互联网时仍可搜索、查看系统报告位置、管理收藏及准备草稿；应用位置需要连接Mac。

Q3：用户确认手机App切后台、锁屏或划掉后由Mac继续现有会话；明确恢复或会话断线、Mac睡眠、服务退出时结束。App仅在前台持续观测系统位置，不保存后台轨迹。控制页生命周期和真实外设连接健康状态分开处理。

Q4：用户要求“尽量无线配置”。不将首次USB连接作为已接受条件；优先复用已有网络开发配对、完成无线安装及应用扫码授权。新设备的系统配对按受支持方式引导，USB仅在确实受限时说明原因并提供可选方案。

Q5：用户选择先用免费版，完善后考虑付费和上架。首版使用Personal Team开发签名，接受现有7天有效期约束；安装续签尽量由Mac侧辅助，不承诺无需用户操作的永久安装。付费购买及商店上架不属于本轮范围。

## 第二轮结论

Q6：用户确认地图作为主界面，顶部搜索、底部目标卡，区分系统位置蓝点与目标标记；收藏通过面板打开，连接管理和诊断放入设置。

Q7：用户确认收藏支持命名、改名、排序、删除，并提供最近使用目标列表，不记录真实移动轨迹。点击条目先预览，必须明确应用；删除或重命名收藏不影响当前会话。

Q8：用户确认恢复单击执行、不弹二次确认；原页面依次展示已停止报点、等待系统新定位和恢复观察结果。不能确认时保留待确认提示和处理指引，不以停止回执代替真实位置恢复。

Q9：用户确认仅在报点会话活动期间阻止普通闲置睡眠，允许屏幕熄灭；主动睡眠或合盖导致睡眠时结束会话，停止后解除保持唤醒。不修改系统全局睡眠设置。

Q10：用户确认按单次几小时以内的场景设计，以连续2小时作为首轮长时验收目标，去掉实验中的120秒强制结束；用户主动恢复，断线、睡眠及退出仍结束当前会话。

## 推荐技术方案

- iPhone：SwiftUI原生界面、MapKit原生地图和搜索、Core Location前台系统定位观测；长按选点或选择搜索结果/收藏只修改草稿。蓝点位置不会因地图相机移动而改变目标。
- 坐标：继续保留来源、输入参考系与归一化WGS84的契约，新增原生地图来源；以参照点验证本地区域搜索、选点、系统蓝点与报点坐标的一致性，不直接继承网页地图的校准状态。
- 数据：手机本地持久保存收藏、最近使用和草稿，使Mac不在线时仍可操作；首连提供原Mac收藏迁移，保留旧文件。最近使用只记录被接受的目标，默认保留最近20个并可清除。原始系统位置样本只用于当前状态判断，不默认保存轨迹。
- Mac：保留轻量菜单栏入口与托管的后台会话服务，默认手动启动，可配置登录时启动。关闭调试窗口不结束会话；服务退出会清理接收器和报点。二维码、紧急停止、授权撤销和脱敏诊断始终可从菜单栏到达。
- 无线执行：复用固定helper及已验证隐藏媒体会话，建连前预热插件；将无线适配器接入现有会话服务，保留USB作为调试能力。位置供数持续由Mac持有，不依赖手机App后台运行。
- 配对通信：一次性二维码传递服务身份和配对信息，首次Mac明确批准，之后保存可撤销凭据。原生客户端凭据保存在Keychain；采用加密控制连接与服务身份校验，保留旧请求隔离、会话版本与幂等处理。Mac地址变化时重新发现相同受信服务，不因同网或名称相同而自动信任。
- 观察反馈：显示新鲜、有效的系统位置样本及目标距离；使用时间、精度和可选来源信息判定本App是否观测到目标。服务接受目标、报点和系统采用为独立状态；来源未知时明确保留未知。
- 恢复：停止服务端会话并继续读取停止后的新样本；不能仅以距离目标变化、停止ACK或一个来源布尔值宣布恢复。缺少足够证据时展示恢复待确认和操作指引。App不伪造蓝点，也不尝试通过公开API强制重置全系统定位。
- 安装：先使用Personal Team，尽量无线安装及更新，提示实际签名有效期；账号登录在用户本机Xcode完成。付费、TestFlight、商店分发在后续阶段重新评估，不纳入首版交付承诺。

## 用户完整流程

1. Mac手动启动服务，手机完成首版安装；App按需请求相机、本地网络及前台定位权限。拒绝某项权限时明确说明受影响功能，其余地图或收藏功能尽量保留。
2. App扫码，Mac确认一次授权；如系统配件链路尚未就绪，向导区分开发配对与蓝牙/CarPlay连接步骤，尽量无线完成。
3. 手机主地图搜索、长按或从收藏/最近使用选择目标，底部卡片预览后点击应用。
4. Mac预热、连接和供数；App展示系统位置是否接近目标。可以切后台、锁屏或划掉App，回前台读取当前会话和最新定位。
5. 更换目标仍须明确应用；目标切换完成前保留现有状态，失败时不将草稿误显示为生效。
6. 手机点击恢复，或者Mac菜单栏紧急停止；界面显示停止与后续位置恢复观察。
7. 外设链路断开、Mac睡眠或服务退出后，当前会话结束；连接恢复只恢复控制通道，不自动应用历史目标。

## 关键异常与验收

| 场景 | 需要实现并观察的结果 |
|---|---|
| Mac不在线 | 手机仍能操作有网地图、系统位置、收藏和草稿；应用按钮明确提示需连接 |
| App被挂起或划掉 | 健康外设会话由Mac继续；重开后展示真实状态，不把旧蓝点当新样本 |
| 控制连接暂不可达 | 显示状态未同步；不能声称停止成功或擅自重发应用；Mac保留紧急停止入口 |
| 外设链路断开 | 结束当前会话、停止供数；重连后必须用户再次应用 |
| 冷启动新运行时 | 插件预热先于无线建连，首帧成功且隐藏后才能报点 |
| 恢复尚无新样本 | 停留在等待/待确认状态，显示最后更新时间及简短指引 |
| Mac普通闲置/息屏 | 活动会话按用户选择保持唤醒；主动睡眠仍清理，停止后释放唤醒约束 |
| 免费签名到期 | 明确续签/重装步骤，不影响Mac侧停止入口；不把重装等同于自动恢复旧会话 |
| 2小时运行 | 连续检查连接、真实订阅、报点、隐藏状态、App前台位置观测及最终恢复；单次通过不当作永久稳定保证 |

## 实施顺序

1. 原生最小可运行验证：免费签名尽量无线安装，读取并展示当前系统位置；与已验证无线会话核对目标采用及停止后的样本，确认App内观察闭环。
2. Mac后台与无线适配：预热、隐藏、清理、睡眠策略、调试入口、手动启动与可选登录启动。
3. 原生扫码与控制：持久授权、加密连接、重新发现、状态同步、明确应用和恢复。
4. 完整地图界面与数据：搜索、选点、收藏、最近使用、原Mac收藏迁移。
5. 体验和真机验收：A/B切点、App前后台/锁屏/划掉、网络中断、Mac睡眠退出、恢复、续签升级及2小时连续运行。

- 四件事必须区分：Xcode开发设备配对、免费开发签名安装、App扫码控制授权、蓝牙/CarPlay配件配对。App二维码不替代系统级配对。
- 2026-10-30的既有设备查询记录显示当前iPhone已配对、通过localNetwork连接、开发者模式enabled；该记录是历史成功证据，不当作此刻的连通性检查。
- 当前选定Xcode为26.6。Apple的新Device Hub提供Xcode27与iOS27+的首次无线配对流程；不自动升级Xcode。当前手机优先复用已有配对，安装是否可完成仍需后续真机验证。

## 换网后的补充要求与当前状态

用户明确指出 Wi-Fi 环境会变化，不应要求手工维护应用内的网络配置。实现已改为识别当前网络，按需使用系统钥匙串的对应凭据，不另存 Wi-Fi 密码；自动检查不会反复弹出钥匙串授权框。系统确实拒绝访问时才显示准确原因，并保留 Mac 上的显式授权入口。MAC 的定位权限仅用于 Wi-Fi 信息，不采集 Mac 坐标。

2026-11-01 补充：用户要求管理员确认只发生在初始化时，之后连接与重启复用授权。上述“不另存”调整为不在应用配置或普通文件中保存密码；允许将初始化成功的网络凭据保存为用户钥匙串中的应用专属条目，按当前 SSID 复用。自动连接不得自行弹管理员密码框；新网络首次初始化、密码更新或钥匙串访问失效时，由用户从 Mac 菜单主动处理。Mac 登录密码不由应用保存。

扫码控制与 CarPlay 位置执行分别判断。新网络的参数读取成功，不等于完整 CarPlay 会话成功；当前验收边界见 `native-app-validation-2026-10-31.md`。
